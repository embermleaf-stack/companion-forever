# UI kit brief: AI-generated interface art (optional)

Status: proposed, 2026-11-07. Docs only. No art has been generated for this brief. Not a legal clearance: the output terms and ownership of any generator are UNVERIFIED (see "Tool terms" below).

Always supply [STYLE-GUIDE.md](STYLE-GUIDE.md) (palette, pastoral hand-painted direction, "do not" list) with each prompt below. Job ids are UI-001 to UI-010 (one per item below; UI-007 also has variants UI-007a and UI-007b). Queue entries live in [art-queue.md](art-queue.md) and copy-paste prompts in [prompts-copy-paste.md](prompts-copy-paste.md).

## Why this exists, and the fallback

The app already ships hand-authored interface art, so nothing below is required:

- Button sprites: `icons-and-imagery/final/btn-{primary,secondary,danger,disabled}*.svg` (48 px, 9-slice source, generated by `icons-and-imagery/final/build-button-sprites.mjs`), rasterized to `apps/mobile/assets/art/ui/btn-*.png` (1x/2x/3x).
- UI glyph sprite: `icons-and-imagery/final/ui-sprite.svg`.
- Art registry: `apps/mobile/src/art.ts` and `apps/web/src/art.ts`. Each entry has a job id, asset, alt text, `provisional` flag and `enabled` flag.

AI-generated versions are optional and swappable. To replace a hand-authored asset, add the new file, point its registry entry at it, and keep alt text. If the AI result fails the checklist, set `enabled: false` or keep the existing file. The UI must work with no AI art at all.

## Shared rules

- **Shared negative prompt** (paste into the separate negative field, or append as `Avoid: ...` if the tool has none):

  `text, letters, logo, watermark, signature, figures, people, faces, photorealistic, 3d render, glossy highlights, lens flare, glowing drop shadow, flaming border, dragon-scale border, brand name, named artist, film still, recognizable character, existing game character, game or studio trade dress`

  "Low contrast" is deliberately left out of this list. The background tile (UI-006) needs it, and the button states must still read.
- **Style:** pastoral hand-painted anime-fantasy look, watercolor and gouache, clean expressive ink linework, soft colour fills, warm lantern light from the upper left. No gloss, no glow halos, no 3D.
- **Palette (Emberleaf):** ink `#14171F`, slate `#1F2430`, vellum `#E8DCC0`, ember `#E0702B`, leaf `#5E9E5A`, bronze `#B58A4A`, candle `#F6D98A`.
- **Names:** never name an artist, studio, film or game in a prompt, filename or note. Describe the look only.
- **Original design only.** Reject anything that resembles an existing game's UI, frame, button or ornament. When in doubt, regenerate or drop it.
- **Grids are a request, not a guarantee.** Generators do not honour pixel grids. Generate at any square size, then crop, resize and slice to the exact sizes below.
- **Staging only.** Outputs go to `icons-and-imagery/staging/` with the job id in the name (for example `UI-001_buttons_v1.png`). Nothing moves to `final/` without a provenance entry and owner approval.

## Items

Sizes are exact export sizes. "9-slice" means the image is split into 9 regions, the corners stay fixed and the edges and centre stretch.

### UI-001: Button sprites (primary, secondary, danger; normal, pressed, disabled)

- **Purpose:** GameButton and similar controls. Primary = Ember, secondary = Aged Bronze with Slate, danger = Rust.
- **Output:** one sheet, `ui-btn-sheet.png`, 768 x 384 px, transparent background. Fixed grid of 3 columns (primary, secondary, danger) by 3 rows (normal, pressed, disabled); each cell 256 x 128 px. Each button is a centred 224 x 80 px rounded rectangle inside its cell. Slice each button as 9-slice with left and right caps 24 px, top and bottom caps 20 px; the centre stays flat.
- **Prompt:**

```text
#UI-001 button sprites, primary, secondary, danger
Hand-painted pastoral fantasy UI button set in watercolor and gouache: three rounded-rectangle buttons side by side with soft wash fills and clean expressive ink outlines, thin Aged Bronze double-line edge, soft inner shadow. Left to right: primary button in Ember orange, secondary button in Aged Bronze with slate, danger button in muted Rust. Top row normal, middle row pressed (slightly darker, inset shadow), bottom row disabled (desaturated, flat, pale vellum). Fixed 3 by 3 grid, even spacing, transparent background. Each button is symmetric with a flat empty centre. Original design. --ar 2:1 --no text, letters, words, logo, watermark, signature, figures, people, faces, flame, dragon scales, photorealistic, 3d render, lens flare
```

### UI-009: Splash lantern, 8-frame flicker sheet

- **Purpose:** Animated lantern on the splash screen. The frames are flicker-only: same lantern, only the flame, glow radius and tiny embers change.
- **Output:** One sheet, 2048x256, eight frames of 256x256. Staging name example: `UI-009_splash-lantern-sheet_v1.png`. Frame order is a loop (8 wraps to 1).
- **Post-processing:** Crop the sheet into eight 256x256 frames and check that the lantern sits on the same pixels in every frame (overlay the frames at 50 percent opacity). Export the sheet and a frame list; the app steps the frames by code.
- **Acceptance (item):** Lantern identical in every frame (same silhouette and position, within 2 px). Flame varies smoothly. Frame 8 to frame 1 is seamless. No scene or background in the frames. Midjourney may not hold identical frames; if it cannot, use the fallback below.
- **Tool terms:** UNVERIFIED (see Tool terms below). Each output needs a provenance entry before merge.
- **Prompt:**

```text
#UI-009 splash lantern, 8-frame flicker sheet
Sprite sheet of eight frames in one row, left to right, in hand-painted watercolor and gouache with clean expressive ink linework. Each frame shows the same small hanging iron lantern on a short chain from the top centre of the frame, in Aged Bronze with Candle gold glass and a soft Ember flame. The lantern is identical in size, shape, colour and position in every frame. Only the flame, the soft glow radius and a few tiny floating embers change, in a smooth flicker cycle that loops from frame 8 back to frame 1. Glow fades softly to transparent at the frame edge. **Fallback (no new art):** if the generator cannot hold identical frames, discard the sheet. The app animates the existing lantern art from the registry in code: a glow pulse, a slight sway and a few drifting embers drawn as small shapes. This needs no extra art. Respect reduced motion: show the static lantern when the device asks for it.
```

## Post-processing (all items)

Firefly connector capabilities are limited: it can crop, resize, remove a background, adjust and expand existing images. It cannot generate images from text. Generation must be done by the owner in an external tool (the Firefly web app, another tool with an API, or a human illustrator). Before any connector call, run `adobe_mandatory_init` as the connector instructions require.

1. Crop to the grid cells or to the single shape, then resize to the exact sizes above (Lanczos or bicubic for scaling down).
2. Remove the background if the tool did not output transparency. Use `image_remove_background` (connector) or a manual mask. Check the edge for halo fringing.
3. Slice where the item is 9-slice or stretch-able. Check that the caps and the stretch regions match the stated insets.
4. Seam test for UI-002 edges and UI-006: offset the image by half its width and height and look for seams. Fix seams by hand; do not accept a tile that shows one.
5. Optional: quantize to 8-bit PNG if the file is over 300 KB (the image-file limit in IMAGERY.md).
6. Export PNG (or WebP) to `icons-and-imagery/staging/` only. Log the tool and job in `credit-ledger.md` and each output in `provenance.md`.

## Acceptance checklist

- [ ] Edges are clean, with no fringe, halo or cut-off shapes
- [ ] Symmetric left to right (and top to bottom for UI-002, UI-006)
- [ ] No baked-in text, letters, logos or watermarks
- [ ] Centre is flat where the item is 9-slice (buttons, panel, tab, toggle)
- [ ] Tiles seamlessly where relevant (UI-002 edges, UI-003 stretch, UI-006 tile)
- [ ] Legible at 48 px: each state reads by shape, not by colour alone
- [ ] Disabled and pressed states are distinguishable from normal
- [ ] Palette matches the Emberleaf values in STYLE-GUIDE.md
- [ ] Nothing from the "do not" list in STYLE-GUIDE.md; no game or studio trade dress
- [ ] Provenance entry filled (PROVENANCE-TEMPLATE.md), alt text written
- [ ] Owner approval recorded before anything reaches `final/` or `apps/*`
